# Shared Fabric transport (Issue #5 foundation and Issue #6 roles)

This integrates the producer described in [SHARED_PROTOCOL.md](SHARED_PROTOCOL.md) with native shared work and current Viewer, Member and Administrator roles. An in-process dedicated-server socket test is distinct from the separate common-only server smoke process; neither establishes collaboration between two distinct external clients (Issue #8 / AC-17).

## Registration and lifetime

The common entrypoint registers `shared_v1` in both play directions and `shared_control_v1` clientbound before receivers. Common classes reference neither Minecraft client classes nor optional mods. Client transport registration runs independently of the optional Litematica adapter and existing local-work service; supporting a channel never selects shared mode.

One server runtime owns `SharedProjectService` rooted in Minecraft's configured saved-world root. Construction queues startup I/O; no tick waits for readiness. Hello receives LOADING while that service initializes, then one capabilities response when readiness is known. Unsafe/corrupt/future-schema startup reports UNAVAILABLE and never makes blank authority. Shutdown disables sends, rejects new work, and drains accepted wire/store work on lifetime-owned background threads.

Negotiation uses the historical `shared_v1` payload with both the 45-byte frame header and nine-byte Hello message envelope at version 1. Its inner proposed version is 2 for the current client. A historical version-1 server can therefore read the frame and reply with the unchanged one-byte UNSUPPORTED control; a historical client proposing version 1 receives the same diagnostic from the current server. The current codec accepts version 1 only for this exact single-frame Hello, and all application traffic remains version 2. Socket tests exercise a registered current server and a test-only parser frozen to the historical v1 format; they do not establish acceptance on an external v1 deployment.

The actual receiver derives actor UUID only from `context.player()`. Actor is absent from request payloads. The wire worker receives immutable token, actor and fragment/command data; game objects stay on the server thread. It assembles, decodes and serializes snapshots on a single bounded worker, and service writes remain on the producer's serial store worker. Immutable completions return through a bounded queue polled on the server thread.

Fabric JOIN can precede the peer's play channel advertisement. Admission therefore also follows channel REGISTER through a bounded queue deferred to a later tick, or the first actual receiver with an installed listener. REGISTER never queries an addon while its constructor is running. An existing native Fabric `PacketContext` stores exactly one typed attempted-listener reference; a replacement listener replaces that reference. This prevents repeated rejected registration/payloads from generating capacity replies, without an application map of rejected peers. A session captures the native listener and actor, then resolves the listener's current player and validates both actor and listener at each receive/send. Ordinary respawn can replace the player entity without replacing this connection or admission slot. Disconnect cleanup uses the captured listener identity, so the replacement entity releases the original slot while a later listener's session remains protected.

Content enqueue and every actual scoped fragment send use `publishIfAuthorized`. They also check the current runtime, exact player/session, both advertised clientbound channels, negotiated protocol and complete subscribed scope. The short publication callback only enqueues bounded immutable work or sends one frame; it never performs disk I/O or waits for a future. Discovery supplies current authorized names with `publishDiscovery` at its actual send. Its maximum 128 bounded summaries fit one frame (under 42 KiB), and this explicitly bounded encoding/send uses the same four-frame tick budget. No captured recipient list authorizes a later send.

Committed command and administration events are processed once in their owning live runtime independently of requester-specific reply eligibility. A departed or incompatible requester cannot suppress another eligible subscriber's delta, manifest invalidation or access removal. Command deltas precede the requester's ACK. An eligible administration snapshot is enqueued before its invalidation; administration events are then published outside the requester eligibility path, including when that path found no eligible requester. The serial encoder and whole-message outgoing queue preserve this order so the client's invalidation clearing cannot discard initial fragments of that correlated snapshot. Each recipient still passes the existing current connection, subscription and authority gates. AccessRevoked targets only its internal recipient. Its wire payload contains scope and no row/name/note/participant contents. It drops that subscription and queued private content; later worker completions still pass current scope and authority gates. The client keeps writes blocked until an explicit fresh join. Creation/admin request IDs correlate responses and are not durable idempotency keys. Uncertain creation is never automatically resent.

## Client contract and native journal

Client INIT registers per-connection receivers capturing the actual listener. A delayed render callback cannot address a replacement listener. JOIN creates a separate transport lifetime and sends one Hello; DISCONNECT sends nothing, disables shared writes and retains the last snapshot honestly unsynchronized. There is no offline mutation queue or automatic resnapshot retry.

`SharedClientState` owns the fixed confirmed snapshot and a separate contiguous delta cursor. Only a snapshot or the next consecutive delta advances that cursor. ACK adoption requires full scope, current installed manifest membership and a newer rowVersion; it cannot recreate removed rows. Buffered deltas during join are finite. Gap, overflow, failed assembly, incompatible protocol or invalidation blocks writes pending deliberate fresh join. For the selected scope, the reducer retains maximum known project revision and manifest version from installed state, applied/gap deltas and invalidation. A same-scope explicit join preserves those fences; an older snapshot cannot enable writes. Switching scopes resets the two fences and requires a correlated fresh join. Buffered contiguous deltas may follow an earlier fixed snapshot and then advance its cursor normally.

Client request/result histories are bounded. Snapshots require the exact outstanding request, its complete scope/world and the revision/manifest fences; selection replies also require the current selected request. Administration snapshot replies are observable for the caller but do not silently reconfirm definitions or enable edits. Command results resolve only their exact original operation, authenticated actor, connection token, full scope and returned task identity. Uncorrelated connection diagnostics never terminally resolve individual unknown commands. Save failure never supplies optimistic row state. Selection clears old requests/snapshot replies and hides other-scope result presentation; AccessRevoked clears private snapshots, matching cached replies/results/requests and incomplete transfers. Original uncertain commands remain separately retained and never become cancellation or success through these presentation clears.

`result(UUID operationId)` is current-binding presentation: it requires the original live actor/token and the selected full scope. `result(AdmissionContext original, UUID operationId)` is original journal confirmation: it checks retained result plus original admission metadata, exact operation/scope and the same live actor/token, without requiring that scope to be currently selected. A legitimate delayed ACK can therefore confirm its original journal after a scope switch, without adopting or displaying its row in another binding. Wrong actor, token or full scope returns no result. Original confirmations survive selection in a bounded 64-entry ephemeral history; Task 3 must consume/persist them promptly rather than treating this cache as durable journal storage. Replacement JOIN clears all histories; the explicit-context getter cannot retrieve them from a replacement account/connection. Revocation removes matching private outcomes. No automatic replay or unsolicited production ACK history is provided.

The sole production row-send entrypoint is:

```java
CompletionStage<Boolean> SharedClientNetworking.submit(
    SharedCommand command, DurableAdmission journal);

CompletionStage<Boolean> DurableAdmission.persist(
    AdmissionContext context, SharedCommand command);

record AdmissionContext(UUID actor, UUID connectionId, ProjectScope scope) {}
```

The native controller durably persists the **exact original immutable command**, authenticated actor, full scope and independently validated local binding before completing true. Persistence and saved-source hashing run off the render thread. The transport rechecks the original live connection, capability, synchronization, scope and current row permission after asynchronous admission before encoding the command. Fragment sending also checks the current connection and subscribed scope; the server checks current authority for the actual authenticated actor. A bounded admission mailbox serializes enqueue with close, rejecting any post-close completion and settling queued transport futures false; future callbacks run outside its short monitor. This does not cancel or remove a durable journal command. It never redirects admitted work into another account/connection/world.

The Boolean result reports transport admission only, never durable server success. False after disconnect or loss of synchronization does not prove a durable command was cancelled; the journal retains its uncertain state. True also requires the matching authoritative result before confirmation. `unconfirmedOperations()` observes only the original live actor, connection token and currently selected full scope. It returns no old command contents to another selected scope or replacement connection/account. The internal bounded unknowns remain retained across presentation clears/disconnect; the durable client journal retains the original admission context. This observation grants no replay authorization or reconnection recovery. Never automatically resend creation/admin or manufacture success from a connection diagnostic. Only one scope is subscribed per connection; material and region bindings remain independent.

## Wire boundary and limits

`SharedPayload` wraps the producer frame with a four-byte length. It rejects missing, oversized, truncated and trailing frame bytes before allocating its bounded array, then uses the producer's strict decode. Maximum registered payload bytes are 61,480 (61,476 producer frame plus length). Application fragments retain the producer's count/size/deadline checks regardless of native payload splitting. These are capacity limits, not measured throughput, latency, heap use or 20-client performance.

`shared_control_v1` is one unsigned byte: LOADING=0, CAPACITY=1, INVALID_INPUT=2, UNSUPPORTED=3, UNAVAILABLE=4, RESYNC_REQUIRED=5. Unknown values/trailing bytes are rejected. This transport-only diagnostic does not alter the producer's authority/archive schema. Both clientbound channels must be advertised; older peers lacking the diagnostic channel are incompatible. Unknown servers produce an unavailable state, with no external lookup or periodic traffic.

| Resource | Limit |
|---|---:|
| Admitted shared connections per owned server | 20 |
| Pending one-shot capacity diagnostic player references | 20, no shared session or worker admission |
| Deferred channel registration listener references | 20 |
| Server incoming frames per tick / per connection per tick | 64 / 4 |
| Server sends per tick, including diagnostics/discovery | 4 |
| Client sends per tick | 2 |
| Wire worker waiting jobs / active worker | 64 / 1 on each side |
| Server concurrent service requests / completion queue entries | 64 / 64 |
| Server completions processed per tick | 16 |
| Client decoded messages / admission completions / outstanding requests | 64 each |
| Client decoded/admission completions processed per tick | 16 each |
| Per-connection pending discovery responses | 4 |
| Pending command observations / snapshot/result history | 64 each |
| Buffered deltas while joining | 64 |
| Server aggregate incoming transfer reservations | 128 MiB |
| Client incoming transfer reservations | 128 MiB |
| Server outgoing reservations / client outgoing reservations | 128 MiB / 64 MiB |
| Encoded outgoing message slots | 64 per runtime |
| Snapshot encoding reservation | 64 MiB per wire worker |
| Queued input-frame reservations | 7,868,928 bytes per runtime |
| Native packet write reservations | 8 packets, 3,934,464 conservative bytes per runtime |
| Outgoing transfer / request / initial negotiation lifetime | 30,000 monotonic milliseconds |

Transfer reservations count twice the declared message bytes so incomplete fragments plus the completed copy remain admitted during consumption. Both periodic expiration and an arriving fragment detecting expired incomplete work release its reservation and signal resynchronization; arrival cannot hide the expired transfer before periodic detection. The transport wrapper fails that arriving frame before new admission, a stricter resync boundary than the producer's standalone reassembler. Encoding reserves before serialization; outgoing admission reserves a slot/bytes before copying outside its short queue monitor. Preparing copies count toward the same 64 slots. A cancellation generation captured before serialization rejects old preparation after clear/remove; removal conservatively cancels all preparing copies, while retaining other connections' already queued messages. Outgoing queues hold one encoded message and slice one fragment per send poll; they do not allocate a complete fragment list. Native write reservations use a one-shot release shared between each write future and synchronous send failure. Core models, authority retention, and upstream Minecraft/Netty allocations are additional memory; the table is not a total server heap guarantee.

Excess shared peers remain Minecraft-connected. At the first compatible play admission after JOIN/channel advertisement the server queues at most one bounded, canSend-gated CAPACITY diagnostic; unadmitted subsequent requests are dropped without reply amplification. If even that bounded diagnostic queue is saturated, the peer receives no shared capabilities and the client negotiation deadline reports unavailable. Capacity, malformed input, deadline and completion-queue failure clear/block the affected shared flow and require deliberate resync; there is no immediate retry storm.

## Verification boundaries

`runSharedTransportTest` uses a separate test-only mod and official mod-ID filter, a real Minecraft registry buffer and an actual socket to an in-process dedicated server. Its test world is a fixed relative child of the configured test run root. Fabric's builder deletes that test directory, so it proves no restart persistence. The socket fixture probes an ephemeral loopback port and fails on allocation failure; a probe-to-bind race remains a fixture prerequisite, not application behavior.

The focused task requires a fresh log and `Shared transport all assertions PASS` after resource closure, and rejects Fabric's explicit test-thread exception marker even if the Java process exits zero. It exercises actual near-max C2S/S2C registered frames, unsupported Hello/control and deliberate renegotiation, actor-derived mutation/ACK/delta, discovery/list-scope denial, manifest invalidation and access removal. A forced test journal delayed across a selected-scope change must not send into that scope; its original unknown remains observable only after deliberate same-connection original-scope resync. Test setup grants a synthetic creator's project to the actual connected Viewer through the core service. A bounded test-only incoming-message mixin observes the raw-wire Viewer's actual content-free DENIED and can hold exactly one real decoded ACK callback until a scope change. Its release must confirm the original journal context while hiding the row from current-binding presentation and rejecting changed actor/token/scope contexts. This is basic callback/context coverage, not actual replacement-login/reconnect acceptance. Production transport still authenticates the Viewer from its socket connection. Test-only journal/observation/mixin/setup code is excluded from the application JAR.

`verifySharedTransport` also audits common/core bytecode and the application JAR. The separate `verifyServerSmoke` retains the Phase 0 isolation checkpoint and additionally waits up to 200 ticks for asynchronous authority readiness, with no optional client mods/classes allowed. `verifyPhase2 :fabric:verifySharedTransport -PacceptMinecraftEula=true` composes the retained core/build/two original client processes/isolated server gates and focused socket gate; the EULA flag remains an explicit caller decision. These task descriptions are verification boundaries, not substitutes for their actual completed output.

Focused lifecycle regressions additionally hold genuine accepted core outcomes through the real wire Processor/completion queue, remove an explicitly synthetic initiating token, and verify that the one actual subscribed Viewer receives a committed delta, manifest invalidation and access removal with private-cache clearing. The test-only token is not a second authenticated external client. An actual native respawn request must replace server/client player entities on the same listener, preserve a shared request/response, and release its admission slot on disconnect while the owning server remains alive. A deterministic bounded-mailbox test exercises observed-open, close/drain, then asynchronous enqueue and verifies that the real transport future settles false. These test controls/mixins remain excluded from the application artifact; the default socket run executes every case. The optional `transportRespawnFirst` test property changes only regression order for independent behavior-failure diagnosis.

The multi-tick administration snapshot regression observes actual notification/frame order and uses at most one real decoded invalidation callback plus one real final snapshot frame to establish the cancellation interleaving when notification arrives first. Worker barriers verify genuine incomplete reassembly before notification clearing and its released reservation afterward. It requires the actual correlated committed snapshot and actual decoded invalidation, without silently reconfirming shared writes. Snapshot-first delivery proceeds without those controls reordering it.
